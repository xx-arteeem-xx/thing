# Thing — план проекта

> Цифровое существо, которое живёт на сервере само по себе. Ты — наблюдатель.
> Рабочее название проекта: **thing**. Имя существа не зафиксировано — назовёшь, когда захочешь.

**Статус документа:** черновик плана, версия 1. Реализация не начата.
**Целевые платформы:** сначала локально (16 ГБ RAM), потом VPS 2 vCPU / 4 ГБ RAM / 100 ГБ SSD.

---

## 1. Что строим и зачем

Три части:

1. **Мир** — небольшая песочница-автомат, где у каждой клетки есть вещество, температура и правила взаимодействия. Коллизия встроена в саму модель (клетка занята или нет). Из комбинаций веществ возникают технологии: огонь, стекло, металл, инструменты, укрытие.
2. **Тело** — 2D-организм из сегментов и суставов с физиологией: кровь, кислород, глюкоза, температура, раны, боль. Он может ходить, тянуться, брать, строить, копать. Ему больно. Он умирает.
3. **Мозг** — два контура. Быстрый рефлекторный (крошечная сеть, 60 Гц, учится сам в рантайме) и медленный языковой (локальная LLM 1.5B, дообученная LoRA в Colab, генерирует мысли по-русски и ставит цели).

**Критерий успеха:** существо живёт неделями без вмешательства, само двигается, исследует мир, находит новые для себя вещи, ведёт осмысленный дневник — и при этом ты можешь параллельно работать на том же ноуте, а потом уехать на сервер.

**Чего в проекте принципиально нет:** разговора с тобой. Ты не можешь ему ничего сказать, подсказать, наградить или наказать. Ты смотришь. Единственная твоя сила — воскресить.

## 2. Жёсткие инварианты (не обсуждаются при реализации)

| # | Инвариант | Почему |
|---|---|---|
| И1 | Симуляция живёт в headless-процессе, браузер — только окно | Вкладка умирает, душится в фоне, ноут засыпает. «Жизнь» не может зависеть от открытого таба |
| И2 | LLM никогда не вызывается из игрового цикла | Один вызов на 40 токенов = секунды. Иначе ноут встаёт и тик рвётся |
| И3 | Тело управляет крошечная сеть, а не LLM | LLM не умеет 60 Гц и не должна |
| И4 | Мир материи — клеточный автомат, не физический движок частиц | Настоящая физика/химия на слабом железе невозможна. Автомат даёт 90% эффекта за 3% цены |
| И5 | Симуляция детерминирована при фиксированном seed и снапшотится | Иначе нельзя ни учиться воспроизводимо, ни пережить перезапуск |
| И6 | Никакого внешнего сигнала награды и никакого внешнего обучения в рантайме | Режим наблюдателя. Вся мотивация внутренняя |
| И7 | Смерть терминальна; `revive` недостижим из пространства действий существа | Структурная гарантия, а не договорённость. Проверяется тестом |
| И8 | Один и тот же код локально и на VPS, различия — только в конфиге | Иначе переезд превратится в переписывание |

## 6. Время, тик и детерминизм

- Мировые часы: фиксированный шаг **16.67 мс** (60 Гц), аккумулятор, максимум 3 догоняющих тика за кадр (защита от «спирали смерти» при просадке CPU).
- Физика тела: 2 подшага по 8.33 мс (120 Гц) внутри мирового тика.
- Физиология: 30 Гц.
- RNG: xorshift128+, состояние в снапшоте. Никаких `Math.random()` в симуляции.
- Порядок обновления внутри тика строго фиксирован: `вход → погода → мир → тело → физиология → политика → события → снапшот(если пора)`.
- Числа: физика тела — float64 (детерминирована на одной архитектуре), мир — целочисленный, чтобы снапшоты совпадали бит-в-бит при локальном тесте.

## 7. Мир (Фаза 0)

### 7.1 Сетка

- По умолчанию **512×256** = 131 072 клетки. Облегчённый режим `384×256`.
- Три плоских массива:
  - `mat: Uint8Array` — вещество (0..~48)
  - `aux: Uint8Array` — битфлаги и вариант (мокрое, горит, заряжено, стадия роста, прочность)
  - `temp: Int8Array` — температура со сдвигом (значение −128…127 °C, шкала 1 °C)
- Активность по чанкам 16×16: чанк помечается грязным, если в нём что-то изменилось. Спящие чанки не пересчитываются — это даёт 3–10× экономии на статичном мире.
- Двойной буфер, порядок обхода снизу вверх со случайным сдвигом по X (убирает «артефакт течения»).

### 7.2 Материалы (~48)

| Категория | Вещества |
|---|---|
| Порода | камень, песок, земля, глина, гравий, соль, пепел |
| Металлы и руды | руда железа, руда меди, железо, медь, расплавленное железо |
| Органика | дерево, листва, трава, семя, росток, плод, мясо, кость, уголь |
| Жидкости | вода, лава, масло, смола, кислота, спирт, грязь |
| Газы и энергия | пар, дым, ядовитый газ, водород, огонь |
| Продукты | стекло, кирпич, керамика, верёвка, факел, инструменты (кирка, топор, нож) |
| Пусто | воздух |

Каждый материал — запись в таблице: плотность (как падает/течёт), теплоёмкость, температура плавления/горения, проводимость, что выделяет при нагреве, чем растворяется.

### 7.3 Реакции и законы

Правила — таблица вида `(A, B, условие) → (C, D, Δтепла)`. Примеры ядра:

| A | B | Условие | Результат |
|---|---|---|---|
| дерево | огонь | — | огонь + уголь + дым + тепло |
| лёд | — | T > 0 | вода |
| вода | лава | — | камень + пар |
| песок | — | T > 800 | стекло |
| руда железа | уголь | T > 1100 | железо + пепел |
| кислота | железо | — | соль + водород |
| семя | земля + вода | время | росток |
| росток | — | время + свет | трава / плод |
| глина | — | T > 600 | кирпич |
| смола | — | T > 120 | огонь |

Законы, которые работают всегда: гравитация и сыпучесть, течение жидкостей, теплопередача между соседями, конвекция газов, горение с распространением, давление газа в замкнутом объёме (упрощённо — по количеству газа в регионе).

Погода (флаг конфига): сутки 20 мин, ночь/день, дождь, гроза с молниями (бесплатный источник огня).

### 7.4 Как существо меняет мир

Существо действует **физически**, а не через меню крафта. Руки — две точки с радиусом до 1.5 клетки. Доступные действия:

`взять` · `положить` · `поставить(вещество)` · `ударить(направление, сила)` · `соединить(A, B)` · `есть` · `пить` · `толкать` · `тянуть`

Инструмент в руке меняет параметры действий: кирка даёт копать камень, топор — валить дерево, нож — разделывать. Соединение двух предметов в руках даёт **рецепты**: палка + камень → топор, палка + смола → факел, волокно + волокно → верёвка. Это и есть возникающее «дерево технологий», а не заранее прописанный сценарий:

1. **огонь** — трение палки о дерево, удар кремня о железо, молния
2. **обжиг** — глина → кирпич, песок → стекло
3. **плавка** — руда + уголь → металл
4. **инструменты** — металл → кирка/топор/нож → добыча ускоряется
5. **строительство** — стены, крыша, ёмкости, факелы
6. **земледелие** — семена → еда (переход от собирательства к запасам)
7. **крепления и ловушки** — верёвка, смола

### 7.5 Журнал открытий

При первом в истории появлении комбинации (вещество в такой-то роли, рецепт, достигнутое состояние) в SQLite пишется событие `discovery`. Это:
- лента «что он нашёл нового» в UI;
- источник сигнала новизны для любопытства;
- измеримая метрика развития: **новых открытий в час** (см. §15).

## 8. Тело (Фаза 1)

### 8.1 Скелет

16 сегментов (жёстких тел), 15 приводимых суставов:

| Группа | Сегменты | Суставы |
|---|---|---|
| Корпус | грудь, таз | поясница (1) |
| Голова | голова | шея (1) |
| Руки ×2 | плечо, предплечье, кисть | плечо, локоть, запястье (6) |
| Ноги ×2 | бедро, голень, стопа | бедро, колено, стопа (6) |
| Итого | 2+1+6+6 = 15 тел (+2 «пальца» в кистях позже) | 15 |

Сустав = шарнир с ограничением угла и предельным моментом (усталость мышц снижает предел).

### 8.2 Физика

Verlet + констрейнты расстояний + угловые пределы, 20 итераций решателя, 120 Гц. Столкновения сегментов с миром — через выборку клеток в AABB сегмента. Столкновения сегментов между собой — отталкивание по расстоянию. Всё это ≈0.1 мс на кадр.

### 8.3 Управление

Моторные примитивы (низкий уровень) — каждая нога/рука управляется небольшой сетью или запрограммированной CPG-раскладкой:

`стоять · идти_влево · идти_вправо · тянуться · схватить · отпустить · ударить · копать · есть · пить · бежать · свернуться · спать`

Высокоуровневый выбор примитива и направления — задача рефлекторной политики (5–10 Гц). PD-контроллер держит позу между переключениями. Это ключевое упрощение: без него обучение полноценной двуногой ходьбы с нуля не сходится за разумное время ни в Colab, ни где-либо ещё.

### 8.4 Физиология

~35 переменных, обновление 30 Гц, простые ОДУ + событийные правила:

| Система | Переменные | Норма | Логика |
|---|---|---|---|
| Кровь | объём (5.0 л), давление, насыщение O₂, гематокрит | 5.0 л / 100 мм рт.ст. / 98% | кровопотеря → падение давления → шок |
| Сердце | ЧСС 60–180, ударный объём | 70 | адреналин и гипоксия поднимают ЧСС |
| Дыхание | частота 12–40, O₂, CO₂ | 14 | голова в не-воздухе → гипоксия |
| Метаболизм | глюкоза, гликоген, жир, гидратация, ATP | 5 ммоль/л | расход на движение и терморегуляцию |
| Температура | ядро 37 °C, конечности | 36.6–37.5 | переохлаждение / перегрев / ожоги |
| Ткани | список ран: место, тяжесть, кровотечение, инфекция, боль | пусто | рана без обработки инфицируется за часы |
| Гормоны | адреналин, кортизол, дофамин, эндорфин | база | стресс, страх, обезболивание |
| Драйвы | голод, жажда, усталость, боль, страх, любопытство, скука, комфорт | 0..1 | это и есть мотивация |

### 8.5 Боль

Боль — не украшение, а механизм:
- ноцицептивный сигнал по региону (0..1) от ран, ожогов, переломов, кислоты, удушья;
- при превышении порога — **прерывание текущего примитива** и рефлекс отдёргивания (мгновенно, вне политики);
- отрицательный вклад в награду и сильный драйв, который политика учится устранять;
- эндорфин при тяжёлой травме даёт обезболивание и шок — реалистичная и полезная для выживания деградация поведения;
- в UI — карта боли по телу.

### 8.6 Смерть

Терминальное состояние конечного автомата. Причины (каждая даёт отдельную запись во вскрытии):

| Причина | Механизм |
|---|---|
| Кровопотеря | объём крови < 3.0 л → гиповолемический шок → остановка сердца |
| Асфиксия | насыщение O₂ < 40% дольше 60 с |
| Отёк мозга / перегрев | ядро > 42 °C |
| Переохлаждение | ядро < 28 °C |
| Обезвоживание | гидратация = 0 трое суток |
| Истощение | глюкоза + гликоген + жир = 0 |
| Сепсис | суммарная инфекция выше порога |
| Ожог/кислота | суммарное повреждение тканей |
| Травма | разрушение жизненно важного сегмента (голова, грудь) |

После смерти: симуляция мира продолжается (мир живёт), тело становится объектом, политика останавливается, LLM генерирует последнюю мысль и останавливается. **Оживить может только ты.**

### 8.7 Вскрытие

Экран смерти: хронология жизни, причина и цепочка причин, минимум/максимум по каждому органу, список ран, последние 20 мыслей, все открытия. Это твоя основная награда как наблюдателя.

### 8.8 Возрождение

`POST /revive` → новое тело, сброшенная физиология, тот же мир, **сохранённые** долговременная память и дневник с пометкой «поколение N». Политика может стартовать с сохранённых весов (или с нуля — флаг конфига). Технически: единственный мутирующий вызов, не связанный с наблюдением (§11.1).

## 9. Рефлекторный контур (Фаза 2) — ядро проекта

### 9.1 Наблюдения (~120 чисел)

| Группа | Размер | Содержание |
|---|---|---|
| Проприоцепция | 30 | углы 15 суставов + скорости |
| Вестибулярный аппарат | 4 | наклон корпуса, скорость, высота головы |
| Контакт | 16 | есть ли опора под стопами/кистями, сила реакции |
| Боль | 8 | по регионам |
| Драйвы | 8 | голод, жажда, усталость, боль, страх, любопытство, скука, комфорт |
| Внутренние датчики | 8 | O₂, кровь, глюкоза, температура, ЧСС, адреналин, гидратация, целостность |
| Зрение | 18 | сетка 9×2 в конусе перед головой: вещество (вложение 8) + температура |
| Тактильность рук | 8 | вещество в кистях, вес, температура |
| Память о недавнем | 20 | хеш-признаки последних 10 посещённых состояний |

### 9.2 Действия

- Непрерывные: 15 целевых углов суставов (или моментов) — нормализованные.
- Дискретные: примитив (13 вариантов) + действие рукой (9 вариантов).
- Высокоуровневая политика выбирает примитив/направление на 5–10 Гц, низкоуровневая сеть ведёт суставы на 60 Гц.

### 9.3 Сеть и алгоритмы

- Сеть: MLP 128×128 (~40k параметров), опционально GRU 64 для краткой памяти. Веса — Float32Array в снапшоте.
- **Этап A (моторы):** эволюция (CMA-ES / NEAT) для каждого примитива. Дёшево, параллелится в Colab на CPU, не требует тонкого reward shaping, даёт устойчивую походку за минуты-час.
- **Этап B (выбор):** PPO/SAC поверх примитивов, вход — §9.1, выход — примитив. Это уже лёгкая задача, влезает на CPU.
- Colab нужен для скорости, но **не обязателен**: эволюция моторов может идти и локально за ночь.

### 9.4 Внутренняя награда (единственный источник мотивации)

```
r = w₁·новизна(s)                  ошибка предсказания RND + счётчик посещений
  + w₂·Σ снижение драйвов          голод↓, жажда↓, боль↓, страх↓ — «хорошо»
  + w₃·открытие                    первое в истории сочетание/рецепт
  + w₄·выживание                   небольшой бонус за каждый прожитый час
  − w₅·боль                        мгновенный штраф
  − w₆·энергия                     стоимость действий (лень тоже должна быть невыгодна)
  − w₇·повтор(s)                   штраф за топтание в одном состоянии
  − w₈·ущерб                       потеря тканей, крови, инструментов
```

Веса — в конфиге, подбираются вручную. Это самая «ручная» часть проекта.

### 9.5 Антидегенерация (обязательно, иначе проект умирает)

Два классических способа провала и защита от них:

| Провал | Признак | Защита |
|---|---|---|
| «Сел в угол» | действия однообразны, новизна = 0, драйвы не растут | несколько конкурирующих драйвов, штраф за повтор, растущий дискомфорт от бездействия, опасный мир |
| Wireheading | находит петлю самостимуляции вместо исследования | запрет прямого доступа политики к сигналу «открытие», затухание новизны по посещениям, обнаружение петли (энтропия действий → 0) |
| Забывание | новые навыки ломают старые | replay-буфер, EWC-регуляризация, регрессионный набор навыков перед каждым сохранением |
| Смерть от любопытства | лезет в лаву бесконечно | врождённый штраф за боль/ущерб + страх как драйв |

### 9.6 Онлайн-обучение

- PPO-апдейт каждые N шагов прямо в процессе (веса маленькие, CPU хватает).
- Replay-буфер на 200k переходов в кольцевом файле.
- **Сон** (раз в сутки, 20–40 мин реального времени): медленный апдейт, прогон регрессионных тестов навыков, откат если стало хуже, запись снапшота.
- Каждое сохранение весов — версионируется; при деградации автоматический откат на предыдущую версию.

## 10. Языковой контур (Фаза 3)

### 10.1 Что он делает (и чего не делает)

Не чат. LLM вызывается по таймеру (60–120 с) или по значимому событию и делает четыре вещи:

1. **Мысль** — короткий внутренний монолог по-русски, 1–2 предложения на поле.
2. **Цель** — намерение, которое уходит в высокоуровневую политику как подсказка выбора примитива.
3. **Рефлексия** — во время «сна»: сжатие прошедшего периода в запись дневника и список выводов.
4. **Дневник** — итоговая сводка дня по-русски, читаемая тобой.

Мотора не касается вообще.

### 10.2 Формат мысли

```
[12:04:31] ОЩУЩЕНИЕ: в левой ноге горит, дышать тяжело
[12:04:31] МЫСЛЬ:    я слишком близко к лаве и уже обожжён
[12:04:31] НАМЕРЕНИЕ: отойти к воде
[12:04:33] ДЕЙСТВИЕ:  бежать влево
[12:04:38] РЕЗУЛЬТАТ: боль стихла, ожог остался
```

Ты видишь не «мысли модели» (это всегда сгенерированный самоотчёт, и это надо честно понимать), а связную причинную цепочку: ощущение → мысль → намерение → действие → результат. Именно она интересна для наблюдения.

### 10.3 Вход для модели: сводка интероцепции

Собирается детерминированным шаблонизатором на TS (не моделью) — это дёшево и стабильно:

```
ВОЗРАСТ: 3 ч 12 мин (поколение 1)
ТЕЛО: кровь 4.1/5.0, O2 94%, глюкоза 3.8, температура 37.1, боль: левая нога 0.6
РАНЫ: ожог левой голени, кровотечение слабое, инфекция нет
ДРАЙВЫ: голод 0.7, жажда 0.3, усталость 0.5, страх 0.8, скука 0.1
ВОКРУГ: впереди лава (5 кл), справа вода (3 кл), сзади камень
В РУКАХ: палка
ПОСЛЕДНЕЕ: 3 раза пытался пройти вперёд, отступал из-за боли
ПАМЯТЬ: 2 дня назад ожог уже случался у лавы; вода помогает
```

### 10.4 Модель и рантайм

- **Qwen2.5-1.5B-Instruct Q4_K_M** как основная (≈1.0 ГБ файл, ~1.3–1.6 ГБ RAM с контекстом 4096).
- Опционально 3B Q4 локально на 16 ГБ — качество русского заметно лучше, но на VPS 4 ГБ не поедет.
- Рантайм: `llama-server` отдельным процессом, `-t 2 -c 4096`, `MemoryMax=1.6G`, рестарт по падению.
- **Честно про качество:** 1.5B по-русски пишет посредственно. Компенсируем: (а) LoRA на русских данных, (б) жёстко короткий формат вывода, (в) шаблонный каркас, где модель заполняет поля. Существуют русско-адаптированные варианты Qwen (семейство RuAdapt) — проверить при старте Ф3.

### 10.5 Датасет

Три источника, суммарно 5–20 тыс. примеров:

1. **Логи прогонов Ф1/Ф2** (основной) — реальные состояния, размеченные «учителем» офлайн: более крупная модель (7B в Colab или разовый прогон через API) пишет эталонные мысли. Дёшево и по делу.
2. **Синтетика по сценариям** — боль, страх, голод, находка, смерть, дождь, холод, встреча с преградой. Покрывает редкие, но важные случаи.
3. **Самостоятельные мысли с фильтрацией** — отбрасываем повторы, пустое, бессмысленное; оставляем удачные.

Формат: chat-template, system-промпт по-русски задаёт личность и запрещает «ассистентский» тон; ответ — строго JSON с полями `ощущение / мысль / намерение / цель`.

### 10.6 Colab-пайплайн

1. Загрузить датасет из репозитория (JSONL).
2. Unsloth + Qwen2.5-1.5B-Instruct, LoRA `r=16, alpha=32, lr=2e-4`, 2–3 эпохи, `max_seq=2048`. **T4: 20–40 мин.**
3. Оценка на удержанном наборе: формат, русский, отсутствие повторов, попадание в тон.
4. Мердж LoRA, конвертация в GGUF `q4_k_m` через llama.cpp.
5. Чекпоинты — на Google Drive (сессия рвётся, нужен resumable-скрипт).
6. Скачать GGUF (~1 ГБ) в `data/models/`, заменить файл — модель обновилась.

### 10.7 Память и саморазвитие без градиентов

Ключевая честная мысль: **настоящее «самообучение» LLM в рантайме на CPU невозможно.** Работает другое, и его достаточно:

- **Эпизодическая память** — каждое значимое событие в SQLite: время, тип, состояние, мысль, исход. Поиск при сборке промпта — BM25 + свежесть + важность (никаких эмбеддингов = экономия RAM).
- **Рефлексия** — раз в сутки/сон модель сжимает период в запись дневника и извлекает «уроки» («лава обжигает», «вода снимает боль», «огонь даёт тепло»). Уроки попадают в промпт навсегда.
- **Рост библиотеки навыков** — успешные последовательности действий фиксируются как именованные навыки.
- **Периодическая LoRA-консолидация** — если есть GPU-окно: раз в несколько дней дообучение на накопленных удачных мыслях. Не обещаем в реальном времени.

### 10.8 Антидегенерация мыслей

- Порог новизны: если сводка почти не отличается от предыдущей — мысль не генерируется (экономия и меньше воды).
- Детектор n-граммных повторов: при зацикливании — смена температуры и шаблона, запись в журнал аномалий.
- Обязательная привязка к фактам: мысль, противоречащая состоянию (говорит «я сыт» при голоде 0.9), отбрасывается и перегенерируется.
- Метрика: **доля повторяющихся мыслей за сутки** (цель < 15%).

## 11. Наблюдение (UI и API)

### 11.1 Read-only контракт

Полный список мутирующих эндпоинтов — исчерпывающий:

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/revive` | единственная игровая сила наблюдателя |
| POST | `/pause` `/resume` | операционное, для переезда и отладки |
| POST | `/snapshot` | операционное, ручной снапшот |

Всё остальное — `GET`. Автоматический тест обходит таблицу маршрутов и падает, если появился мутирующий эндпоинт вне этого списка. Отдельный тест («capability test») пытается вызвать `revive` изнутри симуляции и из пространства действий существа — должен получить отказ. Так И7 держится не на честном слове.

### 11.2 Панели

1. **Мир** — вид сетки, скорость времени, масштаб, температура/вещество под курсором.
2. **Тело** — скелет, карта боли, раны, органы в реальном времени (кровь, O₂, глюкоза, температура, ЧСС), гормоны, драйвы.
3. **Мысли** — поток с таймстампами; фильтры по типу; сохранение в файл.
4. **Дневник** — суточные записи по-русски.
5. **Открытия** — лента «первый раз в истории» (огонь, стекло, топор, укрытие).
6. **Вскрытие** — после смерти.
7. **Метрики** — возраст, тики, новизна/час, энтропия действий, повторы мыслей, латентность LLM, аптайм, RAM/CPU.
8. **Кнопка «Возродить»**.

### 11.3 Трафик

Не гнать сырые кадры. WebSocket: при подключении — keyframe (сжатые массивы мира), дальше — **диффы изменившихся чанков 16×16 c RLE**. В статичном мире это десятки байт в секунду. Мысли и события — отдельные JSON-сообщения. Целевой трафик: <100 КБ/с при активном наблюдении.

## 12. Форматы данных

**Снапшот** `data/snapshots/…vvs` — контейнер:

```
magic "VVS1" | version | tick | RNG-состояние | epoch
[секция MAT][секция AUX][секция TEMP]      сырые сетки, сжаты
[секция BODY]                              JSON: позы, скорости, суставы
[секция PHYSIO]                            JSON: органы, раны, драйвы
[секция POLICY]                            Float32Array весов + версия
[секция EVENTS]                            хвост событий с прошлого снапшота
```

Сырые ~2 МБ, после сжатия **150–400 КБ** (сетки из однородных веществ жмутся отлично).

**Событие** (SQLite, таблица `events`): `id, ts, tick, type, severity, json`. Типы: `birth, pain, wound, discovery, milestone, death, revive, thought, skill, anomaly`.

**Мысль** (таблица `thoughts`): `id, ts, generation, feeling, thought, intention, goal, action_taken, result, discarded(bool), discard_reason`.

**Конфиг** `config/local.yaml` (пример):

```yaml
world:   { width: 512, height: 256, tick_hz: 60, weather: true }
body:    { physics_hz: 120, physiology_hz: 30 }
reflex:  { policy_hz: 60, primitive_hz: 8, online_learning: true }
lang:
  model: data/models/qwen2.5-1.5b-instruct-q4_k_m.gguf
  thought_interval_s: 60
  event_triggered: true
  max_tokens: 120
budget:
  max_cpu_percent: 60
  pause_on_battery: true
snapshot: { interval_s: 60, keep_recent: 120, keep_hourly: 48, keep_daily: 30 }
```

## 13. Бюджеты ресурсов

### Локально (16 ГБ, приоритет — «живость и автономия»)

| Компонент | RAM | CPU |
|---|---|---|
| world + body + physiology + reflex | 300–600 МБ | 10–20% одного ядра |
| LLM Qwen2.5-3B Q4 (или 1.5B) | 2.2 ГБ (1.3 ГБ) | всплеск 2–6 с раз в 30–60 с |
| SQLite, логи, снапшоты | 100–300 МБ | ~0 |
| **Итого** | **~3–4 ГБ** | остаётся запас на работу |

### VPS 2 vCPU / 4 ГБ / 100 ГБ

| Компонент | RAM | CPU |
|---|---|---|
| world + body + physiology + reflex | 350–600 МБ | 15–25% одного ядра |
| LLM Qwen2.5-**1.5B** Q4 | 1.0–1.3 ГБ | всплеск на оба ядра 6–12 с раз в 60–120 с |

| **Итого** | **~2.0–2.6 ГБ из 4** | комфортно |

Диск: модель 1 ГБ + снапшоты с ротацией ~50 МБ + SQLite ~100 МБ/год. 100 ГБ — с огромным запасом.

## 14. Переезд на VPS 2/4/100

Чеклист (проверено на бумаге, выполнять по порядку):

1. **Сборка headless-first** — локально запускать тот же процесс, что поедет на сервер, без браузера. Это главное условие, иначе переезд = переписывание.
2. `config/vps.yaml` — 30–60 Гц, `thought_interval_s: 120`, лимиты бюджета.
3. **Два systemd-юнита:**
   - `thing-world.service` — симуляция, `Restart=always`, `MemoryMax=2.2G`, `Nice=5`;
   - `thing-brain.service` — `llama-server`, `MemoryMax=1.6G`, `Restart=always`.
   Разделение критично: **падение мозга не должно быть смертью существа.**
4. **swap 2 ГБ** (или zram) как страховка от OOM-киллера.
5. **Автовосстановление**: при старте — последний снапшот; перезагрузка сервера = сон, а не смерть. Запись об этом в дневник.
6. **Ротация снапшотов** 60 с / последние 120 + часовые 48 + суточные 30. Иначе диск кончится (см. §12).
7. `logrotate` для логов, лимит на размер SQLite, `VACUUM` раз в неделю.
8. **Безопасность:** ufw (только SSH + порт наблюдателя), исходящий трафик существу закрыт, наблюдатель за HTTP-паролем/токеном, SSH только по ключу.
9. **Мониторинг:** `/health` (тик идёт, аптайм, RAM, латентность LLM) + ежедневная самопроверка, пишущая строку в дневник; алерт тебе, если тик встал.
10. **Бэкап:** раз в сутки rsync снапшота + SQLite к тебе на ноут. Без этого «вечная жизнь» кончается вместе с VPS.
11. Первый запуск — с `pause_on_death: false`, за неделю до отъезда, и наблюдение метрик (§15).

## 15. Метрики: развитие или деградация

| Метрика | Что значит | Тревога |
|---|---|---|
| Открытий в час | находит новое | падение до ~0 → «сел в угол» |
| Энтропия действий | разнообразие | резкое падение → петля/wireheading |
| Новизна состояний (RND) | исследует или топчется | монотонно вниз → деградация |
| Доля повторяющихся мыслей | связность монолога | >30% → нужна перегенерация/консолидация |
| Средняя продолжительность жизни | выживаемость | падение → политика портится, откат |
| Эффективность снижения драйвов | осмысленность | падение → бесцельное блуждание |
| Время в «деятельности» (идёт/копает/строит) | занятость | <20% → скука/апатия |
| Аптайм, тик/с, RAM | здоровье системы | просадки → бюджет/утечка |

Эти метрики — часть UI и пишутся в БД, чтобы смотреть динамику за месяцы.

Каждая фаза — самостоятельная игрушка, которую не стыдно показать. Никаких «сначала всё, потом запустим».

## 17. Риски

| Риск | Вероятность | Мера |
|---|---|---|
| Обучение моторам не сходится | средняя | примитивы + эволюция вместо полного DoF; упрощать до тех пор, пока не заработает |
| Политика деградирует онлайн | высокая | регрессионные тесты навыков, версии весов, автооткат, сон-консолидация |
| «Сел в угол» / wireheading | высокая | §9.5 — конкурирующие драйвы, затухание новизны, детектор петель |
| Русский у 1.5B слабый | высокая | LoRA, короткий формат, шаблонный каркас, опция 3B локально |
| OOM на VPS 4 ГБ | средняя | раздельные процессы, MemoryMax, swap, 1.5B, интервал 120 с |
| CPU steal на дешёвом VPS | высокая | интервал мыслей в конфиге, `nice`, деградация до 30 Гц |
| Диск переполнен снапшотами | средняя | ротация + сжатие (150–400 КБ на снапшот) |
| Сессия Colab рвётся | высокая | чекпоинты на Drive, resumable-ноутбук |
| LoRA забывает базу | средняя | r=16, низкий lr, 2–3 эпохи, регрессионный набор |
| Скука/заброшенность проекта | средняя | каждая фаза играбельна; дневник и открытия дают «сериал», который хочется смотреть |
| Существо ломает себя самомодификацией | низкая на старте | самоизменение только параметров и поведения, версионирование, песочница, без сети |

## 18. Что не делаем

- Настоящую химию и молекулярную динамику — только правила над веществами.
- 3D и фотореализм.
- Обучение LLM с нуля (невозможно в Colab и не нужно).
- Разговор с существом — его нет по замыслу.
- Внешний мир и сеть у существа.
- Мультиагентность, размножение, генетику — возможно, когда заработает одиночка.
- Реальное зрение — только грубый 2D-конус.
- Полный контроль над сотнями мышц — только 15 приводимых суставов.

## 19. Открытые вопросы (решить по ходу, не блокируют старт)

6. Использовать ли русско-адаптированные варианты Qwen вместо базового.
7. Порог новизны для генерации мысли (сколько изменений в состоянии считается событием).
